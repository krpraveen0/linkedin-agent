# Mem0 2.0.18: default `add()` is ADD-only (no automatic UPDATE/DELETE)

Code for the Medium article *"I Told My Mem0 Agent I Went Vegan. It Kept the Memory That I Love Cheese Pizza."*

This walkthrough shows, against the installed `mem0` package, that the default
`add()` pipeline in `mem0ai` 2.0.18 makes a single "ADD-only" extraction call and
never automatically UPDATEs or DELETEs existing memories. The classic
ADD/UPDATE/DELETE/NOOP reconciler prompt (`DEFAULT_UPDATE_MEMORY_PROMPT`) still
ships in the package but nothing on the default path calls it.

## Files

- `inspect_paths.py` — pure source inspection: which prompt the pipeline imports, and whether the reconciler is still wired in. No LLM, no network.
- `run_add.py` — runs mem0's real `add()` pipeline end to end, fully offline. Only the LLM and embedder are stubbed (no API key needed, deterministic). Feeds a fact then its contradiction and reads the store back.

## Setup

```bash
pip install "mem0ai==2.0.18"
```

`qdrant-client` (used here as a local, embedded vector store) is pulled in as a
dependency of `mem0ai`. No external services and no API keys are required —
the LLM and embedder are stubbed in `run_add.py`.

## Run

```bash
MEM0_TELEMETRY=False python3 inspect_paths.py
MEM0_TELEMETRY=False python3 run_add.py
```

## Notes / caveats

- The LLM and embedder in `run_add.py` are stubbed so the run is offline and
  deterministic. The stub LLM returns the facts a real extractor would pull from
  each turn; the point being demonstrated — that mem0's pipeline only ever
  inserts and never reconciles a contradiction — is a property of mem0's own
  code (`memory/main.py`), not of the stub.
- Sorting of the stored-memory list in the output is applied in the script so
  the run is byte-for-byte reproducible; the underlying store order is not
  guaranteed.
- Verified against `mem0ai` 2.0.18 (published to PyPI 2026-08-11). Behavior in
  other versions may differ.
