# Burr statically validates your action's declared reads

Code for the 2026-08-19 Medium article **"I Forgot One Line in My Burr Action. It Read My Source Code and Refused to Build."**

This demonstrates that [Apache Burr](https://github.com/apache/burr) (installed as `burr`, which now redirects to `apache-burr`) parses the *source* of an `@action` function at decoration time and raises if the function reads a state key it did not declare — plus the two blind spots in that check, and the asymmetry that writes are **not** validated the same way.

Verified against `apache-burr==0.42.0` on Python 3.11.

## What each file shows

- `agent_state_contract.py` — an honest agent-turn loop, then a version that reads an undeclared key (raises at decoration), then the two escape hatches: `state.get(...)` and an un-annotated `state` parameter both skip the check.
- `writes_asymmetry.py` — a standard `@action` declares `writes=["turn"]` but also writes `log`; the undeclared key persists into state with no error. Reads are checked; writes are not.
