# Pydantic AI deferred tools + Tool Search — code walkthrough

Companion code for the Medium article *"I Gave My Pydantic AI Agent Three Tools. The Model Saw One Until It Went Looking."* (2026-08-11).

It demonstrates the deferred tool loading + Tool Search feature added in [pydantic-ai v2.26.0](https://github.com/pydantic/pydantic-ai/releases/tag/v2.26.0) (Aug 7, 2026): a tool marked `defer_loading=True` is hidden from the model until the model discovers it with the `search_tools` meta-tool.

The whole demo runs locally against `FunctionModel`. **No API key, no network calls.** `FunctionModel` hands the callback an `AgentInfo` whose `function_tools` field is exactly the tool list the framework would send to a real provider on that request, so inspecting it is like reading the wire.

## Setup and run

```bash
python -m venv venv
. venv/bin/activate            # Windows: venv\Scripts\activate
pip install "pydantic-ai-slim[openai]"   # installs 2.26.0 or newer
python deferred_tools_demo.py
```

## Real captured output

Captured on pydantic-ai 2.27.0, Python 3.11:

```
pydantic-ai: 2.27.0
ToolDefinition.defer_loading field exists: True

no deferral                 -> ['convert_currency', 'get_weather', 'search_flights']
deferral, no search enabled -> []
deferral + keyword search   -> ['search_tools']
[call 1] model sees 1 tool(s): ['search_tools']
[call 2] model sees 2 tool(s): ['get_weather', 'search_tools']
[call 3] model sees 2 tool(s): ['get_weather', 'search_tools']
search_tools returned: {'discovered_tools': [{'name': 'get_weather'}]}
final output: The weather in Paris is sunny, 24C.
```

## What each line shows

- **no deferral** — the model sees all three registered tools, as usual.
- **deferral, no search enabled** — with `defer_loading=True` and no `ToolSearch` strategy, `FunctionModel` sees nothing. The default strategy targets providers with *native* tool search (Claude Sonnet 4.5+, OpenAI GPT-5.4+); on other models you must pass an explicit local strategy or the deferred tools are unreachable.
- **deferral + keyword search** — `ToolSearch(strategy="keywords")` emits the local `search_tools` meta-tool; the three real tools stay hidden behind it.
- **call 1 → call 2** — after searching `["weather"]`, only `get_weather` is revealed. `convert_currency` and `search_flights` remain hidden. A revealed tool stays available for the rest of the run.

## Try a variation

Change the query on call 1 from `["weather"]` to `["currency"]` and re-run. A different tool surfaces (`convert_currency`) while `get_weather` stays hidden, which shows how the reveal is scoped to the search query.
